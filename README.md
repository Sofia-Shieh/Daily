# 留白 Daily Budget

手机和电脑都能使用的个人消费预算网页。

**网页入口：https://sofia-shieh.github.io/Daily/**

## 开始使用

普通入口首次打开为空白账本。使用专属入口可在浏览器中解锁已整理的加密快照，也可选择“恢复我的账本”载入自己的 JSON 备份，或在“预算设置”填写预算后导入账单。

- **预算总览**：15 个类目的季度和年度剩余额度；服饰与美妆分开管理；支持季度结转与消费前试算。
- **消费明细**：搜索、分类修改、手动记账、赠礼与 AA 实际承担金额调整。
- **账单导入**：微信 XLSX、支付宝 CSV、标准 CSV/Excel；导入预览、去重、退款关联、批次撤销。
- **预算设置**：自定义预算周期、储蓄目标与分期预留；备份和恢复全部本地数据。

预算额度与实际现金分开显示。未确认消费单独预留，未确认退款不会增加预算；撤销原消费时，相关退款会转为待确认。

## 数据保存

公开仓库包含程序、空白模板及可选的 AES-256-GCM 加密快照，不包含可直接读取的个人账单、预算、收入或历史均值。快照使用随机密钥；密钥仅由持有人保管，不在仓库、程序或网络请求中。专属入口将密钥置于 URL fragment，网页读取后立即清除，再在浏览器内解密。请勿转发专属入口。

首次解锁会将已整理账本保存在当前浏览器。再次打开同一快照会保留本机后来的修改；已有其他账本时，先选择保留，或备份后再替换，不把原单与净额直接合并。浏览器本地存储包含解密后的数据，请在自己的设备上使用。后续导入账单仅在浏览器处理，不会自动回传至 GitHub。

换设备或清理浏览器数据前，请导出完整备份；在另一设备可通过专属入口载入已整理快照，或恢复最新本地备份。当前不提供账户登录或自动跨设备同步；本机后来新增的记录需要备份迁移。

PDF 不支持直接导入，请使用银行 CSV/Excel 或导入页提供的标准模板。银行与支付平台的同笔扣款可能重叠，导入后请核对待确认记录。

## 本地开发

```bash
npm ci
npm run dev
```

本地开发地址为 `http://localhost:5173`，只供开发机器使用；其他设备请使用上方 GitHub Pages 链接。开发环境可以使用被 Git 忽略的 `.local/` 私有数据，生产构建不会访问该本地接口。

## 检查与发布

```bash
npm test
npm run build
# 开发服务器运行后，使用本环境 Chromium 检查交互和手机布局：
npm run test:browser
# 更新 GitHub Pages 发布目录：
npm run build:pages
```

GitHub Pages 从 `gh-pages` 分支的根目录发布，`main` 保存源码和 `docs/` 构建产物。静态资源已适配 `/Daily/` 子路径。更新程序后重新构建，并将 `docs/` 内容同步到 `gh-pages` 分支。每月账单通过网页导入即可，无需修改代码或重新发布。测试使用明确的虚构数据，不依赖真实个人账单。

## 更新加密快照

将已核对的完整备份保存在被 Git 忽略的 `.local/personal-backup.json`，运行 `node scripts/encrypt-vault.mjs`。脚本将随机密钥保存在 `.local/private-vault-key.txt`（仅本机可读），以新 IV 生成 `public/private-vault.json`，随后按正常流程重新构建并发布。只有密文进入发布目录，密钥和原始备份不可提交。

`node tests/vault-browser.mjs` 可在本地 Pages 预览服务下验证解锁、地址清理、本机数据保护与错误密钥处理，测试只使用虚构记录。
